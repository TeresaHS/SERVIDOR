Aplicación Crear Horario de una Clase

Documentación del proyecto · Ciclos formativos · Análisis, diseño y desarrollo

Enunciado principal

Queremos hacer una aplicación web que permita dar de alta el horario de un grupo indicando la asignatura y el profesor/es que la imparten a cada hora y día de la semana. El proyecto se centra solo en ciclos formativos. Para esto se necesita saber los grupos, sus módulos y quién/es la imparten.

Procedimiento planteado

A la hora de que un directivo/a dé de alta el horario de un grupo, se pasa por varios procesos:

  1. A partir de un listado de grupos, seleccionar el grupo a dar de alta:
    • Si no tiene horario → Clic [+]
    • Si ya tiene horario → Clic [EDITAR] o [VER]
  2. Elegir el módulo de cada franja horaria todos los días.
    • Clic [MODIFICAR PROFESORES]
  3. Elegir el profesor que imparte ese módulo en esa franja horaria todos los días.
    • Clic [DAR DE ALTA HORARIO]
  4. Se almacena el horario del grupo en la BBDD.

Explicación de archivos

En este apartado explico, archivo por archivo, qué hace cada uno y por qué lo he hecho así. Está redactado tal como lo tengo en mis apuntes.

Modelos y conexión

Conexion.php

Aquí guardo la conexión a la base de datos. Ahora uso PDO (PHP Data Objects), que es una capa de abstracción que me permite hablar con la base de datos sin atarme a MySQLi. Con PDO podría cambiar de gestor (MySQL, PostgreSQL, SQLite…) sin reescribir los modelos.

En el constructor creo la conexión con un DSN: mysql:host=...;dbname=...;charset=utf8mb4, y activo PDO::ATTR_ERRMODE = ERRMODE_EXCEPTION. Así, si hay un error de SQL, PDO lanza una PDOException en vez de un warning, y yo la puedo capturar.

Los tres métodos de transacción (empezar, confirmar, deshacer) los uso en guardarHorario() para que, si algo falla, no se quede el horario a medias. Con PDO son beginTransaction(), commit() y rollBack() (con B mayúscula).

ejecutar($sql) es la base de todo: intenta ejecutar la consulta y me devuelve un array con ok, error, codigo y resultado. En el catch capturo PDOException y saco el código de error real de MySQL desde $e->errorInfo[1].

¿Por qué errorInfo y no getCode()? Porque en PDO getCode() devuelve el SQLSTATE (por ejemplo '23000'), que es un código estándar ANSI. Lo que yo necesito es el código específico de MySQL (1062 para duplicado, 1451 para FK…). Ese código está en $e->errorInfo[1], porque errorInfo es un array con tres posiciones: [0] SQLSTATE, [1] código del driver (MySQL) y [2] mensaje del driver.

fetchTodo($sql) me devuelve un array de filas (para SELECT de muchos) usando fetch(PDO::FETCH_ASSOC). fetchUno($sql) me devuelve una sola fila; como PDO no tiene num_rows, hago fetch y compruebo si devuelve false. existe($sql) me devuelve true o false: lo uso cuando solo me interesa saber si hay al menos una fila (por ejemplo, en tieneHorario() y estaEnHorario()).

Grupo.php

Uso todas() en listarGrupos() y en borrarHorarioGrupo(). Uso obtener($id) cuando necesito los datos de un grupo concreto. Uso tieneHorario($id) en la vista v_listarGrupos.php para saber si muestro el botón + o los botones de control. Uso borrarHorarioPorGrupo($id) en borrarHorarioGrupo().

Los métodos anadir(), modificar() y eliminar() están, pero no los uso todavía. Los getters y setters también están, pero no los uso por ahora. tieneHorario() usa el método existe($sql) de Conexion. Si devuelve true, el grupo tiene horario; si devuelve false, no lo tiene. Sigo concatenando el id sin comillas porque sé que el id siempre es un número.

Hora.php

Uso todas() en casi todos los métodos de C_horario (altaHorarioModulos, altaHorarioProfesores, verHorario, guardarHorario) para pintar las filas de la tabla de horario. Uso obtener($id) en mensajeDuplicado() para saber la franja horaria a la que se refiere el error 1062. anadir(), modificar() y eliminar() no los uso.

Horario.php

Uso anadir() en guardarHorario() para insertar cada celda del horario. Uso porGrupo($idGrupo) en altaHorarioModulos(), verHorario() y guardarHorario() para tener el horario de un grupo indexado por [idHora][dia]. Uso borrarPorGrupo($idGrupo) en guardarHorario() para borrar el horario anterior antes de volver a insertarlo.

Los setters los uso en guardarHorario() para preparar cada fila antes de llamar a anadir(). porGrupo() no usa fetchTodo() porque necesito reindexar el resultado como [idHora][dia]; por eso uso ejecutar() y luego un while(fetch(PDO::FETCH_ASSOC)) manual.

Modulo.php

Uso todas() en listarModulos(). Uso obtener($id) en traerModulo(), verModulo(), confirmarBajaModulo() y en C_horario. Uso modulosGrupo($id) en altaHorarioModulos(). Uso estaEnHorario($id) en bajaModulo() para no borrar un módulo en uso. Uso anadir(), modificar() y eliminar() en el alta, modificación y baja de módulos.

estaEnHorario() usa el método existe($sql) de Conexion. Si devuelve true, el módulo está en horario; si devuelve false, no lo está.

Profesor.php

Uso porModuloGrupo($idModulo, $idGrupo) en altaHorarioProfesores() y guardarHorario() para saber qué profesores imparten un módulo en un grupo. Uso obtener($id) en mensajeDuplicado() para saber el nombre del profesor que ha chocado. anadir(), modificar(), eliminar() y todas() no los uso.

Controladores

C_horario.php

Aquí gestiono todo lo relacionado con el horario: listar grupos, dar de alta un horario (primero módulos, luego profesores), verlo y borrarlo. altaHorarioProfesores() recibe los módulos del POST. Si no hay ninguno, va a v_error.php. Si hay, construye un array $celdas con el módulo y los profesores de cada celda, y carga v_altaHorarioPro.php.

mensajeDuplicado($mensajeError) es privado. Recibe el mensaje de error de MySQL y, si es un 1062 de la restricción csu_horario_profesor, extrae el día, la hora y el profesor, y devuelve un mensaje tipo "Isabel ya tiene clase el Lunes de 08:15-09:10".

guardarHorario() es el más complejo: comprueba el idGrupo, empieza la transacción, borra el horario anterior, recorre los módulos comprobando que tengan profesor, inserta cada fila con anadir(), confirma la transacción si todo va bien, y si algo falla la deshace. Si el error es 1062, vuelve a v_altaHorarioPro.php con el mensaje de mensajeDuplicado() y los módulos ya seleccionados.

C_modulo.php

Aquí gestiono todo lo relacionado con los módulos: listar, dar de alta, ver, modificar y dar de baja. validarModulo($codigo, $nombre) es privado y lo uso en altaModulo() y modificarModulo(). Comprueba que el código sea numérico de 4 dígitos y que el nombre no esté vacío.

altaModulo() valida los datos. Si hay errores, va a v_error.php con volver a pedirDatosModulo. Si la BD devuelve 1062, muestro "Ya existe un módulo con ese código". bajaModulo() primero comprueba si el módulo está en horario con estaEnHorario(); si lo está, va a error. Si la BD devuelve 1451 (FK), muestro un mensaje específico.

C_inicio.php

Es el controlador más simple. Solo tiene un método, inicio(), que carga la vista v_inicio.php. No tiene lógica de negocio, solo pinta la página de inicio. Lo tengo como controlador por defecto en config.php.

Vistas

v_altaHorarioMod.php

Muestra la tabla de horas y días para elegir los módulos de cada franja. Recibe $datos['grupo'], $datos['horas'], $datos['modulos'] y $datos['dias']. Cada celda tiene un <select> con los módulos del grupo. La opción por defecto es "No asignado" (value=""). Al enviar el formulario, va a altaHorarioProfesores().

v_altaHorarioPro.php

Muestra la tabla de horas y días, pero en cada celda con módulo muestra los profesores disponibles para elegir uno. Recibe $datos['celdas'], $datos['horas'], $datos['dias'] y $datos['idGrupo']. Si hay un mensaje de error (por un 1062), lo muestro arriba en rojo. Cada celda con módulo tiene un input de texto deshabilitado con el nombre del módulo, un hidden con el id del módulo, y un radio por cada profesor.

v_error.php

Vista genérica de error. Recibe $datos['mensaje'] y $datos['volver']. Si no llega volver, el botón Volver va a inicio por defecto. La uso en todos los controladores cuando algo falla (validación, error de BD, id inexistente, etc.).

v_confirmar.php

Vista genérica de confirmación. Recibe $datos['mensaje'], $datos['urlSi'] y $datos['urlNo']. Sirve para cualquier confirmación (baja de módulo, borrar horario de grupo, etc.). El botón SÍ va a urlSi, el NO y el Volver van a urlNo.

Migración a PDO

¿Qué es PDO y por qué lo uso?

PDO (PHP Data Objects) es una extensión de PHP que ofrece una interfaz uniforme para acceder a distintas bases de datos. En lugar de usar funciones específicas de MySQLi (mysqli_query, mysqli_fetch_assoc, etc.), PDO me da métodos comunes (query, fetch, exec…) que funcionan igual con MySQL, PostgreSQL o SQLite.

La principal diferencia con MySQLi es que PDO es una capa de abstracción: si algún día cambio de gestor de base de datos, no tengo que reescribir los modelos, solo el DSN de conexión. Además, PDO soporta consultas preparadas de forma nativa, lo que ayuda a prevenir inyecciones SQL.

En mi caso he migrado a PDO porque quería centralizar toda la lógica de base de datos en Conexion y dejar los modelos limpios, sin fetch sueltos ni try/catch repartidos.

Cambios generales en Conexion.php

  • Conexión: ahora es new PDO($dsn, USUARIO, PASSWORD) con PDO::ATTR_ERRMODE = ERRMODE_EXCEPTION. El DSN incluye charset=utf8mb4.
  • Transacciones: beginTransaction(), commit() y rollBack() (con B mayúscula).
  • ejecutar($sql): el catch es de PDOException. Para seguir teniendo el código de MySQL real (1062, 1451…), devuelvo $e->errorInfo[1] en lugar de $e->getCode() (que devuelve el SQLSTATE, por ejemplo '23000').
  • fetchTodo($sql): usa fetch(PDO::FETCH_ASSOC) dentro del while.
  • fetchUno($sql): ya no puede usar num_rows. Hace fetch(PDO::FETCH_ASSOC) y comprueba si devuelve false.
  • existe($sql): método nuevo. Devuelve true si hay al menos una fila y false si no. Lo uso en tieneHorario() y estaEnHorario() para no repetir el fetch en los modelos.

Cambios en los modelos

  • Grupo::tieneHorario(): usa existe($sql).
  • Modulo::estaEnHorario(): usa existe($sql).
  • Horario::porGrupo(): sigue usando ejecutar() y un while(fetch(PDO::FETCH_ASSOC)) manual, porque necesita reindexar el resultado como [idHora][dia]. No usa fetchTodo() porque fetchTodo() no reindexa.

Códigos de error SQL: 1062, 1451 y el array errorInfo

Cuando PDO lanza una PDOException, la propiedad errorInfo contiene un array con tres posiciones: [0] el SQLSTATE (estándar ANSI, por ejemplo '23000'), [1] el código específico del driver (MySQL, por ejemplo 1062 o 1451) y [2] el mensaje del driver.

Con MySQLi, $e->getCode() devolvía directamente 1062. Con PDO, getCode() devuelve el SQLSTATE ('23000'), así que para seguir usando los códigos de MySQL en mi lógica (if($res['codigo'] == 1062), if($resultado['codigo'] == 1451)) leo $e->errorInfo[1].

Así en C_horario.php el if($res['codigo'] == 1062) sigue funcionando igual, y en C_modulo.php el if($resultado['codigo'] == 1451) también.

Transacciones

¿Todo correcto?

ROLLBACK Todo vuelve al estado original

begin_transaction()

Marca el inicio de la transacción. A partir de aquí, todo lo que se haga (INSERT/UPDATE/DELETE) queda pendiente, no visible para otras conexiones (según nivel de aislamiento) y reversible. Internamente ejecuta START TRANSACTION en el servidor.

commit()

Confirma todos los cambios pendientes desde el begin_transaction(). A partir de aquí son definitivos y visibles para todos.

rollback()

Descarta todos los cambios pendientes desde el begin_transaction(). La BD vuelve al estado que tenía antes. 

try {
                $conexion->beginTransaction();

                $conexion->query("INSERT ..."); // si falla, lanza PDOException
                $conexion->query("UPDATE ..."); // si falla, lanza PDOException

                $conexion->commit();
            } catch (PDOException $e) {
                $conexion->rollBack();
                // log, mostrar error, etc.
                echo $e->getMessage();
            }
